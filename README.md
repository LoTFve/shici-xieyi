# 诗词写意

输入一首古诗词，生成它的画面。

- **意象**：诗里写到的具体景物，决定画什么。本体里有 790 个能识别的意象，其中 340 个能画：自己有画法，或沿上位类落到 27 种画法之一，比如杜鹃、雁按鸟画，寺、桥按楼阁画。画不出的（猿、琴、梧桐）也参与时辰、季节和情感推断。景物后面紧跟“绝、无、灭、歇、后”时视为没有，不画，比如“鸟飞绝”不画鸟。
- **意境**：整首诗的时辰、季节和情感，决定怎么画。时辰定天色，季节定山色，情感定饱和度、明暗、雾气、动画快慢和逐字显现的速度。

画面由浏览器用 Canvas 现场绘制，不用图片。

## 页面

- **作画**：全屏画面加竖排诗句，右侧面板列出每一项判断和依据。可以点预置诗，也可以自己粘贴，格式是第一行标题、第二行作者，后面是正文。点意象标签会跳到本体页的对应概念。
- **诗库**：唐诗三百首、宋词三百首、千家诗、诗经、楚辞共 1179 首，可以按集子筛选，按标题、作者、诗句搜索，点一首就去作画。
- **本体**：从这 1179 首汇总出的 791 个概念。左边是概念树，中间是详情（画法、季节、时辰、寄托、象征、各集占比、例句），右边是以选中概念为中心的关系网络图。

网址可以直接分享：`#/p/唐诗三百首/20` 是《江雪》，`#/library?q=明月` 是诗库搜索，`#/onto/雁` 是本体里的雁。

## 本体与大模型

- **基础本体**（`ontology/base.json`，手写）：27 种画法、时辰、季节、情感词表，以及关系，比如渔人需要舟、日不出现在夜里。
- **汇总本体**（生成）：由 DeepSeek 逐首抽取 1179 首诗的意象，再用 `tools/build-onto.cjs` 汇总。`ontology/graph.json` 给本体页浏览；`ontology/runtime.json` 给作画用，每个概念带触发词、画法、季节和时辰倾向、寄托的情感。审阅报告在 `ontology/review.md`。
- **触发词筛选**：每个写法都拿 1179 首的抽取结果核对过，原文里出现时模型多半没把它当成这个意象的（比如“心”“君”“将”，或“山阿”的“阿”），不用来匹配。
- **规则**：按汇总本体的触发词匹配，长词优先（“寒山寺”先于“山”），地名里的字不按字面画（鹳雀楼不画鸟）。实写比例很低的意象（龙、凤、美人）规则只记不画。时辰、季节没写时由意象的统计倾向推断；情感在单字计分之外，再加上意象寄托的情感（雁寄思乡、猿寄哀愁）。
- **大模型**：后端把诗和汇总本体的全部概念名发给大模型（默认 DeepSeek，任何 OpenAI 兼容接口都行），让它判断每个意象是实景、否定、比喻、借指、用典还是虚写，并给出时辰、季节、情感和原文证据。
- **融合**：模型给的证据必须能在原文里找到，找不到的判断丢弃，改用规则的结果。最后由本体补全依赖、推断缺失的时辰季节、去掉冲突项。

面板里每一项都标出来源：蓝底是模型，绿底是本体推断，红框是和规则判断不同的地方。

## 运行

在项目根目录建 `.env`（已在 `.gitignore` 里）：

```
DS_KEY=你的key
DS_URL=https://api.deepseek.com
DS_MODEL=deepseek-chat
```

`DS_URL` 可以换成任何 OpenAI 兼容接口，`DS_MODEL` 不填默认 `deepseek-chat`。没有 `.env` 也能用，只是只有规则。

```
npm install
npm run build      # 生成诗库并构建前端到 web/dist
npm start          # 后端，托管 web/dist，提供 /api/analyze
```

打开 http://localhost:8000 。

开发前端时另开一个终端运行 `npm run dev`，打开 http://localhost:5173 ，改代码会热更新，`/api` 转给 8000 端口的后端。

## 目录

| 路径 | 内容 |
|---|---|
| `web/src/analyze.js` | 规则分析、本体收尾、与模型融合 |
| `web/src/scene.js` | Canvas 作画 |
| `web/src/pages/` | 作画、诗库、本体三个页面 |
| `server.mjs` | 后端：托管前端，调用模型 |
| `ontology/` | 基础本体、汇总本体、审阅报告 |
| `data/` | 各集诗文（简体）和逐首抽取结果 |
| `tools/` | 转简体、抽取、汇总本体、生成诗库的脚本 |

更新汇总本体：`node tools/extract.mjs <集名>` 抽取，再 `npm run build:onto` 汇总。

## 已知局限

- 不用模型时，意境靠关键词计分，碰到用典、反语、比喻会判错。
- 画法仍只有 27 种：杜鹃和雁都按同一种鸟画，寺和桥都按楼阁画。
- 汇总本体是模型抽取再统计出来的，有归错的地方，详见 `ontology/review.md`。
- 景物的位置是固定的，不同的诗之间会有模板感。
